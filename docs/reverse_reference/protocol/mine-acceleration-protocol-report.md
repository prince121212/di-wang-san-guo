## 已验证事实 / Verified facts

1. 打矿出征预览使用 `0x1520 -> 0x8520`。
2. 正式出征使用 `0x1522 -> 0x8522`，成功响应返回正数 `battleId`。
3. 出征途中的行军符加速使用 `0x1524 -> 0x8524`。
4. `0x1524` 请求体固定为：

   ```text
   battleId/writeLong + itemId/writeShort
   ```

5. 本次中级行军符请求：

   ```text
   battleId = 0x0000000000933d6b
   itemId   = 0x004d = 77 = 中级行军符
   payload  = 0000000000933d6b004d
   ```

6. `0x8524` 响应第一个字段为有符号 `status/readByte`：

   | status | 语义 |
   |---:|---|
   | `0` | 加速成功 |
   | `-1` | 加速失败 |
   | `-2` | 已经行动完毕 |
   | `-3` | 自动 VIP 无法使用行军加速 |

7. 成功响应的状态字节后直接携带更新后的军情数据。本次响应中：

   - `battleId` 仍为 `0x933d6b`。
   - 状态文字已从“攻占水晶矿”变为“攻占水晶矿，战斗进行中”。
   - 行军剩余毫秒由 `1,804,488` 变为 `0`。
   - 更新时间为 `2026-07-14 12:56:19.636 +08:00`，与加速请求时刻一致。

8. 行军符只能用于前往资源点的出征途中；战斗结束后的返回途中不能使用。

## 接入建议

1. 在 `0x8522` 确认出征成功并取得 `battleId` 后、进入驻守等待循环前执行加速。
2. 根据设置映射到 `itemId 76-79`，请求体使用 `struct.pack(">qH", battle_id, item_id)`。
3. 发送 `0x1524`，只接受 `0x8524 status=0` 为成功。
4. 成功后刷新宝库，确认对应行军符数量减少，并记录日志。
5. 加速失败不应误判为打矿失败；记录明确原因后继续等待正常行军和战斗。
6. 只对 actionType `2` 的打资源点出征执行，不在驻守召回或返回途中执行。

## 尚未覆盖 / Remaining gaps

- 本轮只验证了“中级行军符成功”。
- 尚未实抓 `-1/-2/-3` 三种失败响应，但客户端响应处理器已确认对应语义。
- 尚未实抓连续使用两张初级行军符；从请求格式判断，每张应各发送一次 `0x1524`。
- 尚未实抓宝库数量在加速前后的响应差异，开发时应通过现有宝库刷新接口二次确认扣除。

## 结论

这轮抓包已经足够开发“选择一种行军符，对打矿去程加速一次”的功能。协议、字段顺序、成功判断、失败状态和调用时机均已确定；剩余抓包主要用于补强失败日志和连续使用多张行军符，不阻塞首版实现。

## 智能选符规则

### 计算基准

1. 使用正式出征后的剩余去程时间，不使用保存设置时的估算值。
2. 优先读取正式出征响应或军情中的剩余时间；暂时无法解析时，可用：

   ```text
   remainingSeconds = max(0, previewArrivalAt - currentServerTime)
   ```

3. 允许最多保留 60 秒自然行军时间。剩余不足 60 秒时不使用行军符。
4. 需要覆盖的加速时间：

   ```text
   requiredSeconds = max(0, remainingSeconds - 60)
   ```

### 选择目标

从当前宝库实际拥有的行军符中枚举可用组合，按以下顺序选择：

1. 组合总加速时间必须优先达到 `requiredSeconds`。
2. 在可达到的组合中，选择总加速时间最小的组合，减少时间浪费。
3. 总加速时间相同时，选择道具数量最少的组合，减少请求次数。
4. 数量仍相同时，优先使用更高级的行军符。
5. 如果全部库存也达不到 `requiredSeconds`，使用当前可提供加速时间最大的组合，尽可能缩短等待。

### 执行规则

1. 每张行军符对应一次 `0x1524` 请求，不在一个请求中提交数量。
2. 每次发送前重新确认 `battleId` 仍处于打资源点去程状态。
3. 每次收到 `0x8524 status=0` 后更新剩余时间和宝库数量，再决定是否发送下一张。
4. 一旦进入“战斗进行中”、驻守或返回状态，立即停止继续加速。
5. 某张符失败时停止本轮加速，记录原因，打矿任务继续按正常行军等待，不把加速失败等同于打矿失败。
