# 道路速度与城防战斗加成公式静态追踪状态

- 日期：2026-07-05
- 目标：继续追踪 `road_value -> 行军速度/耗时` 与 `wall_value -> 守军战斗力加成` 的精确公式是否能从客户端恢复。

## 1. 结论摘要

1. 已对 `data.b.v/w/x` 与 `k.Y0/Z0/a1` 做全 DEX 引用扫描。
2. `data.b.v / k.Y0`：城墙/城防 current/max。
3. `data.b.w / k.Z0`：道路 current/max。
4. `data.b.x / k.a1`：炮塔 current/max 候选。
5. 这些字段的静态引用只集中在：
   - 数据访问器与初始化；
   - 城池详情/修筑 UI；
   - 修筑请求前输入上限计算；
   - `0x8304 -> k.r0` 修筑响应同步；
   - 当前面板、邻近列表、角色城池列表与地图摘要缓存刷新。
6. 未发现道路值参与客户端本地行军时间/速度计算。
7. 未发现城墙/城防值参与客户端本地战斗伤害、攻防或损兵计算。

因此当前不能从 APK 静态代码完整恢复道路速度公式和城防战斗加成公式；它们更可能在服务端结算侧，或者需要通过动态样本拟合。

## 3. 对服务端重建的影响

- 道路/城墙数值必须实现为服务端权威字段，并在城池列表、详情和修筑响应中同步。
- 行军时间与城防战斗加成初版可以先做配置化公式，不必依赖客户端本地公式。
- 若目标是“高度复原旧服”，需要采集动态样本：
  1. 同起点/终点/兵种/将领，改变道路值，记录出征/阻击耗时。
  2. 同守军/攻军/技能/科技，改变城墙值，记录攻城战报损兵与胜负。
  3. 对样本做拟合，确认线性、分段、百分比或阈值公式。

## 4. 当前边界

- 静态结论只能证明“客户端未见闭环公式”，不能证明服务端原公式不存在。
- 道路不通无法阻击的判定可能也在服务端，客户端仅显示服务端提示。
- 炮塔字段已定位，但炮塔完整战斗机制仍未恢复。
