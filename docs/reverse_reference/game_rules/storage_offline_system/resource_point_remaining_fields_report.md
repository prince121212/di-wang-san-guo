# 资源点 / 攻城目标剩余字段与道路城墙语义补充

- 日期：2026-07-05
- 目标：继续确认 `z5/B5/O5/P5`、`c6/e6/p6/q6`、`K5/L5/n6/o6` 的业务名，并把“道路/城墙”语义边界收窄。

## 1. 本轮结论

1. 对剩余字段做全 DEX 静态引用扫描后，发现 `v5/z5/B5/O5/P5/K5/L5` 与同构字段 `Y5/c6/e6/p6/q6/n6/o6` **只在 `p.f` / `p.c1` 两个响应读取方法里出现**，未发现其他 UI 或逻辑方法读取它们。
2. 因此这些字段当前不能强行命名为“产量/储量”。更稳妥的结论是：隐藏状态、兼容字段、旧 UI 遗留字段或时间戳候选。
3. `M5[]` 有进一步语义：它是 `p.f` 尾部的 ID 列表，读出后与 `q5[]` 做匹配，命中则设置 `N5[matched]=true`。所以它更像“当前列表中需要标记的一组目标 ID”。
4. “道路/城墙”已可进一步确认：
   - `y5 / b6` = 城池道路值候选，高置信。
   - `A5 / d6` = 城墙/城防值候选，高置信。
5. 文本规则确认道路和城墙的作用：
   - 修筑道路能提高城池道路值；道路值越高，军队行动速度越快。
   - 修筑城墙能提高城池防御值；城池防御值越高，驻防在里面的部队战斗力越高。

## 2. 剩余字段静态引用扫描

扫描产物：

- `resource_point_remaining_refs/field_refs.json`
- `resource_point_remaining_refs/field_refs.md`

扫描目标字段：

```text
p.f:  v5, z5, B5, O5, P5, K5, L5, M5
p.c1: Y5, c6, e6, p6, q6, n6, o6
```

扫描结果只有两个命中方法：

| 方法 | 说明 |
|---|---|
| `LscriptPages/game/p;->f(String)` | 资源点/目标列表响应读取，负责读 `v5/z5/B5/O5/P5/K5/L5/M5`。 |
| `LscriptPages/game/p;->c1(String)` | 同构列表响应读取，负责读 `Y5/c6/e6/p6/q6/n6/o6`。 |

未发现 `p.s/p.t/p.q` 或其他 UI 逻辑使用这些剩余字段。因此本轮把它们降级为：协议兼容字段 / 隐藏状态字段 / 时间候选字段。

## 3. `M5[]` / `N5[]` 的标记逻辑

`p.f` 尾部读流：

```text
readLong -> M5_count
M5 = new long[M5_count]
N5 = new boolean[count]
N5[*] = false
读取 M5[]
for each M5_id:
  idx = r0.M(M5_id, q5[])
  if idx != -1:
    N5[idx] = true
```

结论：

- `M5[]` 是一组目标 ID。
- `N5[]` 是当前列表 `q5[]` 对应行的布尔标记。
- 具体标记含义还不确定，可能是已占、已选、可操作、保护中、推荐目标等之一。
- 对服务端重建：如果暂时不确定，可以返回空 `M5[]`，让 `N5[]` 全 false。

## 4. 道路 / 城墙语义确认

### 4.1 UI 标签证据

`scriptPages/game/p.s()` 与 `scriptPages/game/p.q()` 都出现：

```text
di_道路
di_城墙
```

在 `p.s()` 中：

```text
p.f  分支：di_道路 -> y5，di_城墙 -> A5
p.c1 分支：di_道路 -> b6，di_城墙 -> d6
```

所以：

| 字段 | 同构字段 | 语义 |
|---|---|---|
| `y5` | `b6` | 城池道路值 |
| `A5` | `d6` | 城墙/城防值 |

### 4.2 文本规则证据

已有 `sentence_rule_hits.md` 中存在：

```text
【修墙说明】修筑城墙能提高城池的防御值;城池防御值越高,驻防在里面的部队战斗力越高.
【修路说明】修筑道路能提高城池道路值;道路值越高,军队行动速度越快.
```

同时 `scriptPages/game/k.D1()` 出现：

```text
roadvaule
wallvaule
re_粮食城墙
re_黄金城墙
re_粮食道路
re_黄金道路
```

并出现修墙相关常量和文本：

```text
60 粮食 -> 1 点城墙
1 黄金 -> 1000 点城墙
```

### 4.3 对战斗/出征的影响

- 道路值很可能影响行军时间、阻击是否可达、城市之间道路通畅相关逻辑。
- 城墙/城防值影响攻城战：冲城车描述明确“只能对城墙进行攻击，对城墙有强大的破坏力”；文本也说明城防越高驻防部队战斗力越高。

但具体数值如何进入行军时间公式、守军加成公式、城墙生命/防御公式，本轮尚未恢复。

## 5. 字段处理建议

对服务端重建，建议：

1. `road_value`、`wall_value` 必须作为城池/攻城目标核心字段保存和下发。
2. `M5[]` 可以先作为目标 ID 标记列表实现；不确定含义时返回空数组最安全。
3. `v5/Y5`、`z5/c6`、`B5/e6`、`O5/p6`、`P5/q6` 暂按兼容字段保留，初版返回 0。
4. `K5/L5/n6/o6` 暂按时间候选保留，初版返回 0 或合理时间戳；后续抓到真实响应后再命名。
5. 修墙公式可以先按文本实现：`60 粮食 = 1 城墙`、`1 黄金 = 1000 城墙`。修路公式需要继续追 `k.D1` 分支后再定。
