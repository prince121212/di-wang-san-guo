## 关键格式证据

### `0x09` 演员/单位创建候选

观察格式：`09 + byte1 + byte2 + actor_id:u16 + resource_id:u16 + utf_len:u16 + name_utf8 + tail(9字节)`。tail 可拆出层/动作/朝向/坐标等候选字段。

样例：`7-9-1.sc` 中连续创建 `曹操`、`郭嘉`、`哨兵`，后续 `0x06` 文本使用这些角色名发言。

### `0x06` 对白/旁白显示

观察格式：`06 + speaker_or_cmd_id:u16 + duration:u32 + portrait_or_actor_ref:u16 + flags(6字节) + utf_len:u16 + text_utf8 + ui_tail(10字节)`。

样例：`7-9-1.sc@0x93` 提取文本 `哨  兵：报！袁谭与袁尚在冀州城外扎营交战！`。

### `0x0A` 动作/移动候选

固定 18 字节，字段中稳定出现 `actor_or_cmd_id`、`duration`、坐标候选 `x/y`。它通常出现在演员创建后或对白之间，用于推动站位、移动、攻击演出或入场。

## 当前不能过度确认的点

- `0x01/0x0D` 的镜头/延迟字段语义仍需结合客户端解释器或逐帧动态验证。
- `0x05/0x0B/0x0C` 已能按长度解析，但“特效/显隐/路径/批量演出”的命名仍是基于上下文的高置信推断，不是函数名级确认。
- 这些 `.sc` 是剧情/场景演出脚本，不等同于服务端战斗结算公式；它能补齐副本叙事、演员、站位、演出，但不能单独复原伤害计算。
