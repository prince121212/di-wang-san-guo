# 普通建筑规则数值表初步

- 来源：`scriptBuilding.sc` 尾部二进制结构。
- 结构化输出：`building_level_rules_combined.csv`、`building_level_cost_rules.csv`、`building_level_effect_rules.csv`、`building_level_unlock_rules.csv`、`building_level_prereq_rules.csv`。

## 1. 解析结论

1. `scriptBuilding.sc` 原有解析只拿到了建筑名称/描述/图片 ID；本轮继续解析尾部，恢复出每级前置、升级消耗/时间、产出或兵种解锁。
2. 升级成本组格式稳定：`tag/u8; count/u16be; count * (level/u8 + costA/u32be + costB/u32be + costC/u32be + time/u32be)`。
3. 大厅、房屋、农场有产出/容量效果组：`tag=1; count; level + effect_a/effect_b/effect_c`。
4. 兵营类有等级到兵种阶段的解锁组：`00 01; count; level + unlock_stage`。
5. 15 字节前置条件行已结构化保留，但字段业务名仍需结合代码继续验证。

## 5. 当前边界

- `cost_copper_or_A`、`cost_food_or_B` 从数值和错误码看高度疑似铜钱/粮食；`cost_extra_or_C` 当前样本全部为 0，保留为第三成本字段。
- `build_time_seconds` 命名为秒是基于数值规模和 UI 时间显示推断，仍建议动态验证。
- 旧 `buildings.json` 中“最大等级”字段不完全等于尾部成本行数量：大厅/房屋/农场成本行是 15 级，兵营为 10 级，书院为 15 级；服务端重建应优先以本轮尾部规则行数量作为可升级等级上限候选。
- 前置条件 15-byte 行已导出到 `building_level_prereq_rules.csv`，但各 byte 的业务名仍需继续追代码函数。
