# 版本记录

## 开发中

V0.0.3 发布后的后续优化在此累计。

### Android 手机本地 V1

- Android 正式架构从“电脑端 Mobile API 遥控”切换为手机本地核心：APK
  打包同一套单容器前端，本机消息桥连接 Kotlin 账号、配置、调度、协议和
  本地地图；电脑关机时仍可独立运行。
- 密码与 Session 认证字段使用 Android Keystore + AES-GCM 分仓保存，账号
  JSON 和导出不再包含认证秘密；添加账号需明确凭据授权，删除账号同步
  删除密码和 Session 密文，日志统一脱敏。
- Keystore 别名升级到 V2；旧设备密钥无法解锁时清理明文并要求重新登录，
  不让本地 Activity 因 UserNotAuthenticatedException 崩溃。
- 移除生产源码中的远程核心、电脑设置、代理/VPN、协作地图、旧原生页面和
  生产 Mock；正式调度只接受启用且拥有真实 Session 的本地账号。
- 前台服务改为按任务绝对截止时间自适应唤醒，空闲期间释放 WakeLock，仅在短执行窗口持有有超时短锁；任务
  停止锁、重试/睡眠截止时间和每日完成状态可在进程重建后按配置签名恢复。
- 前台通知显示账号和当前任务并保留停止入口；通知权限与电池优化豁免只在
  用户点击启动托管后请求。
- 删除全局 TLS 信任绕过，恢复 Android 平台证书链和主机名校验；连接完成后
  主动释放，请求健康记录按执行线程绑定账号，避免多账号串账。
- 六部因缺少逐项真机动作证据不进入正式任务，手机控件保持禁用；打矿撤防
  历史配置在计划入口强制归零，不能进入未实现协议路径。
- 自动验证基线：Android 399 项、共用前端 470 项全绿；V1 覆盖审计通过。
  逐功能真实动作、6 小时锁屏、网络切换、Session 过期、重启恢复和抓包仍
  需用户明确授权后真机验收，当前不宣称 15 条标准全部完成。

- “常规-常用”的自动加体改为账号级共用出征预检：副本、无损、
  掠夺、打矿和刷黄在检查到将领体力低于用户设定阈值时，均先用
  1 枚活血丹再继续状态/配兵检查；运行中任务每次检查都读取最新公共
  设置，同一将领的并发检查会合并，避免重复消耗活血丹。
- 修复 0x8004 将领解析把体力上限 301 以上的合法将领过滤掉的问题；测试账号
  1608600 的英雄页已从 8 条恢复为接口返回的 11 条。
- 军情页新增“辅助此刻行动”实时区块：从任务引擎本地状态汇总刷黄在途
  编队（几级山贼、坐标、battleId）、副本关卡战斗（第几章第几关，0x8600
  看不到的信道）、打矿驻守和正在准备中的出征；状态以心跳里将领真实
  忙闲（征/战/防/返）定名，每 2 秒随任务轮询更新、每秒原地刷新时长，
  不新增任何游戏服务器请求。0x1600/0x8600 服务器军情分区展示，刷新
  节奏保持“进入页面和手动刷新”不变。
- 按军情专项抓包（20260726_173635）升级 0x8600 解析：副本关卡战斗
  （【副本】targetType=0x0e）与多人副本建队“备战”态、山贼去程尾部
  0x0b、行军中与战斗中按剩余行军时间区分出“出征”态、targetType
  0x03=山贼；修正 marchValue 语义为“剩余行军毫秒”（连续刷新递减），
  军情卡片“剩余时长”倒计时按 快照时刻+剩余 锚定，每秒刷新。
- 副本章末关是多人副本，单人无法挑战：打通模式自动跳过章末关直达
  下一章第一关（修复日志中“副本未确认启动成功：多人副本创建成功”
  的卡死），出征接口对章末关直接拒绝，前端关卡下拉不再提供章末关；
  记录解散组队接口 0x193a/0x893a（只记录，不主动调用）。
- 运行日志按受众分流：日志行在写入时声明是给用户看还是给排障看，未声明
  一律算排障。保存设置底部的黑框和运行日志页只显示用户行（出征、领取、
  使用道具等成功记录，以及功能暂停/无目标/恢复的播报），系统日志侧栏仍
  保留全部明细。此前结构化事件在没有 message 字段时会把整个 JSON 当成
  一行展示给用户——实测占黑框 50% 的行数、76% 的字符，其中 597/772 条只是
  RUNNING 进度心跳。两类日志各有独立保留额度，排障刷屏不再挤掉用户历史。
- 状态播报只报“持续成立”的情况：刷黄每几秒重扫一次目标，曾在四分钟内
  在“无目标/运行中”之间翻转十二次，每次都是真实状态变化却毫无信息量。
  停摆类结论立即播报，采样类状态需持续满一分钟才播报。
- 打矿出征现在有成功记录：成功记录改为按“出征已被服务器确认”这一证据
  识别，不再逐功能写分支——打矿整天都在出征却一条记录都没有，就是因为
  它的分支从来没人写。打矿/掠夺同时补上“编队N > 目标(x，y)”的编队号，
  历史账本里已确认的打矿出征也会在记录页补齐。
- 等待中的常驻任务必须交还账号车道：只要功能声明了“下次什么时候再看我”，
  调度器就把它记成该功能的车道截止时间，而不是听凭各功能自己记得声明。
  此前打矿一个驻守闭环（行军 675 秒 + 驻守/撤防/回闲）会吃掉全部 tick，
  测试账号 1608601 上副本逾期 41 分钟、刷黄逾期 104 分钟，账本里打矿
  112 个 tick 对副本 33 个。同时修正饥饿判定：通过 pending 路径占用车道
  也算“已被服务”，否则打矿跑完闭环后仍被判为饥饿，再靠优先级赢回车道。
- “停下，需要人工”同样要写进账本：功能拒绝动作（例如打矿撤防回执没有
  确认 battleId，读多少次都settle不了，禁止自动重发）时，这个结论以前
  只存在于返回值里，下一个 tick 看到的记录和正常记录没有区别，于是每
  两秒重算一次同样的拒绝并继续占着车道。现在结论落到记录上，功能进入
  既有的隔离路径并在界面上标为“需人工核对”，而不是表现为“正在忙”。
- 打矿补上闭环后半程的记录：出征之后的 驻守→撤防→整队回闲 此前不产生
  任何记录，面板上只看得到出征然后就没声音了。现在撤回完成单独记一条
  “编队N 已撤回 > 目标(x，y)”，用 `mine:recall:{battleId}` 作去重键，
  与出征记录并存而不是互相覆盖。撤防本来就是按 battleId 一次撤回整个
  编队的全部将领，这次只是把它变成看得见的事实。
- 打矿占领成功/失败按证据判定，失败进“角色-提示”：赢和输在结束那一刻
  长得一模一样——将领都回家了。区别只在过程中出现过一次：占领成功会有
  【驻守】，失败则直接【返回】。因此每次军情观察都会把证据累加到待决
  记录上，收尾时直接读结论，而不是从结束状态倒猜。两端的提示页都是从
  用户日志文本派生的，所以失败会被叙述成“打矿：编队N 占领失败，将领已
  自行返回 > 目标(x，y)”，由此出现在提示页；下一轮成功的撤回记录会把它
  清掉。军情期间从未看到过这一轮（重启、刷新丢包）时结论是“未知”，
  不报失败——误报一次不存在的失败比不报更糟。
- 撤防改由将领状态裁决，不再由回执的 battleId 裁决：0x8526 的回执里带的是
  一整份军情快照，其中【返回】事件报的 battleId 和出征时的不是同一个
  （实测发出 41604347、回来 41605271），于是每一轮都卡在“回执未确认”，
  而将领其实早就离开矿点回家了。撤防请求本身带精确 battleId，撤错队在
  请求侧就不可能，所以回执匹配仍算确认、不匹配则记为“已发送待观察”，
  改看将领是否离开“防”——只有撤防生效才会让一个将领离开驻防。将领仍在
  驻防且超过宽限期才交人工，任何情况下都不会自动重发。被拒的回执原文
  一并留存在待决账本里，下次不匹配可以直接查而不用再猜。
- 同类隐患一并修掉（与上面几条同源，都是"结论没落到账本上"或"同一个事实
  被两处各答一遍"）：
  - 内政会复现打矿那次的"每两秒重算同一个拒绝并独占车道"：将领维护/内政/
    背包整理把发送边界存在记录顶层之下，这个事实在异常处理和隔离闸门两处
    各写了一遍，后者只认将领维护。现在两处共用同一个判断。
  - 掉线重连不再丢弃上一会话的结论：原本用白名单搬运，方向反了——结论必须
    被"记得"才能活下来，而忘记是静默的。体力暂停（缺活血丹暂停 30 分钟）
    就在名单外，于是每次重连都解除暂停、立刻再撞体力不足、再写一次暂停；
    测试机 Wi-Fi 每晚断一次，这是个循环不是边角情况。现在默认全部继承，
    本次登录重算的值照常覆盖。
  - 日常任务自我暂停不再静默：日常是七件独立调度的事，状态在下一层，顶层
    播报循环既找不到 lastState 也找不到"日常"的名字，于是签到/领币/俸禄
    因回执不明停摆整个周期时日志上一个字都没有。现在每件事用自己的名字
    播报和恢复。
  - "人工确认修复"的入口不再被一张四项别名表限制在副本/无损/刷黄。
- 一个任务停摆不再拖累其他任务：此前"是否停下"靠 state 字符串是否恰好叫
  "blocked" 判断，于是每起一个新名字就重新掉进同一个坑——副本连续三次未
  确认通关时停在 clear-unconfirmed，既拿不到重试退避也保不住阻塞时刻，
  被当成"立刻就绪"每个 tick 参与竞争；它的出征又是已确认的 accepted，
  发送边界闸门也放行，于是每两秒重算一次同样的拒绝还占着车道。现在
  "需要人工"是记录上的独立事实，调度器按事实而不是按名字判断。
  区分"停摆空转"和"多步轮次正在推进"用的是账本有没有实质变化：将领维护
  每一步被拒也会写"需要人工"，但它每次都在账本里落下新的一步，所以照常
  推进；真正原地不动的才退避，期间车道归其他到期任务。

第一个正式版本基线，以本次交付到 Windows 电脑的便携包为准。

- 交付文件：`帝王三国电脑版辅助-Windows-20260715.zip`
