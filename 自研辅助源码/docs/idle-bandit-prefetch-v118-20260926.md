# V118：闲时山贼预扫与 160 点搜索范围

## 需求与旧实现

用户要求将领出征/战斗期间利用空闲时间准备下一批目标，且把旧 80 点搜索范围翻倍，保留等级、掉落、兵种和配兵设置。

旧桌面 `server.py` 的 `idle_bandit_map_worker` 有小批量扫描、前台业务避让和地图新鲜度控制；账号级旧扫描器会在刷黄任务活动时退出竞争。手机版改用共享常驻核心后，任务枚举仍存在，但没有独立的闲时执行入口。

## 实现边界

- 在共享核心 `_run_automation_recovery_tick` 的末尾接入预扫：先完成正常任务选择、日常任务门禁、所有待决/回程检查截止时间合并，再考虑预扫。
- 只在刷黄已启动、等级至少 30、区服身份已知、当前本地地图模式下工作。不修改云端模式；云端共享模式不绕过协调器扫描。
- 同一账号使用现有常驻车道，不创建第二个扫描线程，不发送出征/治疗/补兵/预占请求。
- 一次最多一个区域，成功后至少间隔 3 秒；请求读取超时 2 秒、最多 1 次尝试；距业务截止不足 3 秒不启动查询。已发出的网络请求不能瞬间抢占，但下一轮始终先处理到期业务。
- 缓存保存该区域所有等级/掉落的真实目标，出征继续使用原筛选条件，并保留已派遣/占用目标去重保护。
- 利用同区服本机共享缓存：最近 120 秒扫描过的区域（包括空区域）跳过；全部新鲜时 30 秒后复查。失败不推进游标；游标和未过滤地图可跨重启恢复。
- 闲时日志使用独立 `banditPrefetch` / `BANDIT_PREFETCH`，不覆盖刷黄任务状态。用户级进度日志最多每分钟一条。
- 旧隐藏默认 80 点自动按 160 点执行；显式其他自定义上限保留。前端、Android 配置映射、共享配置规范化、桌面旧常驻路径保持一致；不改矿点或手动找黄的扫描语义。
- 当前中心 `(91,26)`：旧扫描点 X=66..120、Y=0..54；新扫描点 X=48..132、Y=0..66。仍按距离由近到远排列，旧 80 点是新 160 点的前缀；这不是一个填满的矩形，也不是全图 384 点。
