# V107：打矿纯本地、同机同服共享地图与出征互斥

## 决策与不变量

用户要求手机上两个账号不互抢，不再为打矿使用云端资源。地图描述的是区服
事实，不属于扫描账号；出征占用是持久化业务事实，不是会过期的地图缓存。
因此共享观测与出征账本必须分开，不能仅合并地图就认为并发已经安全。

- `LocalMapStore` 按规范化平台、区服、地图类型建立同机共享文件；身份不完整时
  隔离为账号私有，不能猜测同服。每个扫描格保存未经过账号筛选的规范化真实
  游戏观测，包含玩家占领信息。等级、类型、掉落、兵种、距离仍按各账号配置筛选。
- 每格独立过期；补扫一格不刷新其他格的时间，也不清空其他格。旧宿主快照保留，
  但缺少平台身份、已按账号筛选的旧快照不直接并入新共享池；正常有界补扫填充它。
- 打矿自动/手动入口仅走本地查图与游戏协议，不调用云端查图、扫描租约、预占、
  派遣状态回写；只有打矿而无刷黄的常驻账号不再因打矿续租云端在线状态。
  刷黄云端优先策略不改，本地及兜底路径使用同一个同服观测池。
- 打矿在任何前置变更前，以短锁完成“检查同服全部账号账本＋保存本账号账本”。
  停止账号仍参与互斥；已有本账号账本不能被新目标覆盖。未知或损坏的未决账本
  不能被解释为目标空闲。刷黄沿用已有的同机原子准入与分编队恢复账本。
- 打矿成功回执和目标消费时间同次落盘，闭环完成再次更新消费时间；只有更新的
  游戏空矿观测才能重用目标。行军中观察到的旧空矿不能在归队后直接复用。
  最新玩家占领观测也会阻止手动请求携带的旧空矿信息。
- 打矿无缓存时每批最多 5 个扫描格，按规则持久化扫描游标，避免整图长时间占用
  账号通道。矿点上限、配兵、忠诚、行军上限、加速、驻守/撤防规则不变。
- 迁移只撤销打矿的 `cloud-map dependencyWait`。不清除在途、已发送或未知出征，
  不解除资源不足、将领忙、容量满等原有约束，不修改其他功能的依赖恢复规则。

边界：这是本机协调，不保证其他手机或外部玩家不会同时选择该点；游戏服务器
仍是最终事实来源。本次没有增加账号、开启停止账号或修改账号的筛选/配兵配置。
