# V105：云端优先、本地刷黄兜底

## 根因与第一性原理

吞吐取决于每个可用编队的“游戏行军/战斗/回城 + 必要维护 + 额外空闲”。
共享云端用于避让其他账号，不是发送游戏出征协议的必要条件。线上已经证实
Cloudflare D1 免费写入额度耗尽，旧策略却把这一协调依赖变成刷黄硬依赖，
使空闲编队等待云端；只缩短找目标或轮询时间不能解决这个问题。

本版本按用户最新授权作可用性取舍：云端可用优先共享；云端不可用时，
使用本机真正的山贼/黄巾地图继续刷黄，而不是将云端旧缓存改名为本地地图。

## 实现与边界

- 独立持久化 `brushCloudFallbackJson`，按平台/区服隔离，与真实在线模式
  `cloudMapPresenceJson` 分开，不把云端失联伪装成同服只有一个账号。
- 额度错误、网络/服务故障、心跳缺失，以及副本吞掉的增量/上传失败都进入
  降级；游戏动作开始前最多重入一次本地流程。正常竞争拒绝与参数错误
  不触发降级，真实游戏预检/发送开始后任何云端错误都不能重发游戏动作。
- 本地优先读原快照，继续使用原 TTL、距离、等级、掉落与兵种筛选；没有匹配
  目标则沿原扫描游标每批最多 5 个坐标补扫。原配兵、日上限与启停配置不改。
- 普通故障 60 秒、D1 额度故障 300 秒探测（若服务端重试时刻更早则提前）。
  冷却只限制云端请求，空闲编队仍按原独立调度工作。刷黄 tick 尾部的同步
  心跳也不在降级期占用执行通道；其他功能自己的在线租约策略不改。
- 恢复必须有“真实预占 + dispatching 占用”的双回执，单独心跳/只读成功
  不算恢复，不反复切换或播报假恢复。
- 显式本地路由可以解除旧版刷黄派遣 `dependencyWait`；兄弟编队归队本身
  仍不能解除云端依赖或伪称云端恢复。
- 同机同服目标的“检查 + 新账本写入”使用短锁，停止账号的未结账本也参与
  互斥；各队既有 `sending/uncertain/accepted` 账本、将领占用和原子计数不变。
  已知其他账号的有效租约仍避让，但断云期间无法保证跨设备不竞争。
- 离线新观测写入原事件队列，不联网、不清队列冒充成功。已出征目标的旧
  availability 上传保留但隔离，重启从游戏账本重建；接受出征不是目标死亡，
  因而不伪造 gone。只有真实、更新且不再有在途占用的游戏观测才能解除隔离。
- 手动入口共享同一路由；只持有云端来源目标时，离线需从本地地图重新选取。
  打矿的断云策略不在本次授权内，保持原样。
