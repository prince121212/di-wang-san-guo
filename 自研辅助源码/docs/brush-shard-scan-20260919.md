## 第一性原理与根因 / Root cause

“调度执行了一轮”“游标前进了”“真的查询到了新地图”是三个不同事实。
只有真实查询或明确由同区服伙伴承担的坐标，才可以计为已处理。

`_run_configured_brush_tick` 先将 80 个原始坐标按在线账号分片为 40 个。
该层的 offset 是分片内下标，却把同一 offset 和 batchSize=5 原样传给原始
`_run_brush_search_game_workflow`。后者先截取原始坐标窗口，再和覆盖列表取交集。

例如奇数分片第 5 个位置开始，应查询原始下标 11、13、15、17、19；
原始读取层却只允许下标 5–9，交集为空。之后外层还把“空扫描”当成已处理，
持续推进并绕回，导致远处符合配置的目标永远没有被发现。

原测试把底层扫描函数整体替换为直接接受覆盖列表的假实现，未执行这次错误的
窗口过滤，所以能通过但不能证明端到端的扫描覆盖。

次要问题：无目标提示原用单个全局筛选指纹和计数。8 级、7 级编队每次轮换
都被当成用户修改了筛选，长时间找不到目标也无法达到提示阈值。

## 修复与安全边界 / Changes

1. 原始读取层在完整合法搜索范围内验证覆盖列表，实际只发送已分配的小批坐标：
   每批仍最多 5 次，只读请求仍限速、限时，命中即停，不一次发送 80 个请求。
2. 分片游标只在分片空间解释；在线名单变化后按当前分片长度重校验。
3. 按实际完成的坐标位置保存续扫游标，提前命中不会跳过剩余坐标。
4. 已分配非空坐标却没有实际查询结果时，报 `BRUSH_SCAN_PROGRESS_MISSING`，
   保留原位置，不再声称完成。
5. 无目标查询证据存入各编队既有持久化游标，规则轮换不再清零；
   命中或修改某队规则，只清该队证据。兼容保留旧的当前编队展示字段。
6. 单账号路径、旧云端扫描租约、目标云端预占、将领回闲及未知发送保护不变。
   不更改等级、掉落、兵种、配兵量或自动任务启停设置。
