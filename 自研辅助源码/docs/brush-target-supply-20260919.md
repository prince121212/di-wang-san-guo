## 第一性原理 / First principles

真正的目标供给链路是：

`实际扫描 → 本地匹配 → 待发队列 → 云端确认写入 → 原子预占 → 游戏出征`

本地有目标不等于云端有这条记录；云端没有可领目标，也不能推出游戏地图没有目标。
在线伙伴更不能等同于该伙伴已经完成了分配给它的扫描。
因此此轮重点不是在少数候选之间调整编队分配，而是找出候选在哪一步丢失或停滞。

## 已验证事实 / Verified facts

### 1. 本地发现的目标未进入可领取的共享池

02:37 与 03:20 的真机快照中，176 的地图副本均有：

- 待发目标更新 374 条；
- 待发消失事件 404 条；
- 自己观察过的扫描坐标 40 个。

日志反复出现上报失败，以及目标 `0000000001214fab`、
`00000000012147a9` 的 `unknown-target` 补报。
旧日志不检查上报结果，却声称“已从本地副本重新上报”，掩盖了队列没有推进。

### 2. 静态分片让在线但不继续扫描的伙伴永久占住搜索范围

80 个配置扫描坐标中，旧实现只允许每个账号查询自己的分片：

- 176 的上传记忆覆盖全部 40 个奇数下标坐标；
- 202 的上传记忆只覆盖下标 `0、2、4、6、8`；
- 其余 35 个偶数下标坐标没有这两个账号的观察证据。

202 持续从共享池找到自己的候选，因此不进入按需扫描。
176 没有匹配目标却只能重复自己的 40 个坐标，无法补上伙伴留下的空缺。
这些是扫描区域，不是山贼个数；不能将残缺副本的过滤数量当作全图供给数量。

### 3. 源码中存在独立、可复现的 D1 批量参数错误

`applyGone` 原来为每个 ID 展开一个 `?`。第一条 SQL 另有 4 个固定参数，
而接口和客户端允许一次 200 个 gone ID，所以实际需要 204 个绑定参数。

[Cloudflare D1 官方限制](https://developers.cloudflare.com/d1/platform/limits/)
为每条查询最多 100 个绑定参数。

带生产限制的真实本地 D1 回归：

- 96 条通过；
- 97 条失败：`101 > 100`；
- 200 条失败：`204 > 100`。

原 observations 路由先写 upserts、再处理 gone。后一步失败会使客户端保留整批队列，
从而反复重发前面的更新，后续新目标无法推进。
**此缺陷已由源码和回归确认，但不能将它当作下面单条写入也失败的完整解释。**

### 4. 线上还有独立的写入故障，缩小批量没有恢复

03:14 安装兼容小批量客户端后，上报队列仍未下降。
03:30 使用项目文档指定的 Runtime Client Token 做了有界分离验证：

| 请求 | 结果 |
|---|---|
| 公共区服目录读取 | HTTP 200 |
| v2 observations 空事件（只验证共享模式、不写目标） | HTTP 200，CLOUD_SHARED |
| 手机待发队列中的 1 条真实 upsert | HTTP 500，INTERNAL_ERROR |
| 手机待发队列中的 1 条真实 gone | HTTP 500，INTERNAL_ERROR |
| targets/sync，limit=1 | HTTP 200 |

两条写入探针只是重放已有真实队列事件，没有虚构目标、手工出征或清除手机待发队列。
令牌只在进程内使用，没有输出或落盘。
手机日志也记录了心跳服务异常，但本机 health、共享 Python 核心和前台服务正常。

目前只能确认云端写路径失败，**不能在没有服务端异常的情况下断言是配额耗尽、
数据库异常或线上部署版本问题**。线上 `/health` 不访问数据库，其 200 不能证明写入正常。

## 已完成修改 / Changes

### 客户端（已安装）

1. gone 每批上限 96，兼容尚未升级的旧 Worker；upserts 仍最多 200。
2. 普通副本读取也推进至多一批待发事件，不依赖下一次地图扫描触发重试。
3. 失败保留原队列并以 15 秒间隔限频，不在同一调度调用中无限重试。
4. 新观察到的目标取消尚未发出的旧 gone，避免同一请求先写入又删除它。
5. 补报日志检查指定目标是否真的从队列获得确认；
   本批成功但目标仍排在后面时也不能声称成功。
6. 刷黄先扫描本分片，再按需补扫其余配置坐标；整个顺序每轮覆盖 80 个坐标。
   仍每批最多 5 次查询、命中即停，有候选时不强行启动额外扫描。
7. 持久化扫描顺序指纹，在线名单改变后重校验游标；
   兼容 V101 的合法分片位置，并保留实际查询进度。
8. 不把仅扫描本分片的证据用来提前判定整个区域“筛选过严”。

共享模式内的目标预占与未知出征账本保护没有取消。
